复核对象：`tools/deimv2_trt_2025.py`、`deimv2/tensorrt/report.md` 及其结构化结果，对照指令 S1/S5。未运行 GPU，未更改实现或既有测量数据。结论：当前实测数字和限定范围相符，可作为 **FP16 候选结果** 发布；保留 `partial`、原生默认及非严格等价的决定。发现两项复现/措辞限制，不能据此声称未来任意重跑自动满足全部条件。

## 发现与限制

1. **热缓存条件未在 benchmark 独立强制。** 代码预热为 TensorRT 首图5次，以及原生/后端首图各10次；中/末图在正式30轮中首次出现前未在该阶段显式预读。既有全量评价和反复读取使本次接近热缓存实验，但没有检查 OS page-cache 驻留或控制冷缓存。建议说明“重复读取、未清空 OS 缓存；预热网络使用首图，中/末图此前已用于全量评价，缓存驻留未测量”，避免把三张输入全程热缓存写成程序保证。不必为该措辞改动覆盖现有测量。
2. **未来重跑的权重关联保护不完整。** validate/benchmark 会核对当前 ONNX/engine SHA256 和 TensorRT版本，但 benchmark 从配置重新加载原生 checkpoint，未强制其 checkpoint/config SHA 与导出所用原生资源一致，也未把这些原生哈希直接写进 paired_benchmark。未来替换配置/权重后可能出现不同模型的错误配对。本次独立核对当前 checkpoint/config 与 `strict_load.json` 一致，ONNX/engine 与 `build.json` 一致，故未发现当前结果实际混用。建议后续实现显式资源关联 guard，并为现有结果保留本次独立核对证据；不要把事后核对描述为测量时执行的 guard。
3. **逐层等价未证明。** 全量有限性、输出类别/框几何、候选对齐及最差三例已检查，但没有 TensorRT 每个中间层与原生的数值对应证明。现有报告未声称严格等价且维持原生默认，边界正确。LayerNorm FP16 警告和候选置信度变化不能被整体 AP 预算替代。

## 已验证事实

| 检查 | 复核结果 |
|---|---|
| TensorRT隔离及版本 | 10.6.0；FP16启用、TF32关闭；FP32/INT64输入输出；报告未声称全部层FP16 |
| 原生权重 | strict=True，记录 missing/unexpected 均为空；当前 checkpoint/config SHA256 与严格加载记录一致 |
| 引擎资源 | 当前 ONNX、engine 的字节 SHA256 与 build.json 一致 |
| 输入一致性范围 | preprocess_first_middle_last.json 中3张输入跨环境位级哈希相同；这是抽样核验，不是5,000张逐张输入哈希证明 |
| 配对轮次 | 30轮；COCO image_id 397133、180878、15335 各10次；每轮原生/后端次序交替 |
| 统计值 | 从30条原始记录重新计算 mean/P50/P95/std，全部与 summary 相同 |
| 计时边界 | 每次文件读取→解码→归一化→H2D→GPU forward+post→D2H可消费数组；JSON对象转换和可视化不含；GPU event+同步合理 |
| 收益 | 全30轮后端更快；最小配对节省7.887787 ms，平均节省9.172004 ms；均值比2.191062 |
| AP范围 | 原生/后端 image_ids.json 完全相同，5,000张；300完整候选/图；共同pycocotools，显示阈值未裁评价预测 |
| AP预算 | 0.508610069→0.508069034；绝对下降0.000541035，低于0.005 |
| 最差3例 | 198805/114907/475678；IoU≥0.5对应15/42/24，未对应2/3/2；对应最大xywh分量差0.727142/0.796722/1.369019 px，与报告一致 |
| 未对应解释 | 每个未对应框在另一后端完整300候选中均有同类IoU≥0.5且score<0.25的框；不证明decoder query身份；报告明确此限制 |
| 显存与冷启动 | 设备总已用采样包含其他进程；Torch峰值不含TRT内部分配；顺序加载时间不冒充完整可比cold start |

最大588.643px来自强制二分配对，并非同一物体或同一query的实测位移。报告以IoU门控复核最差三例，同时披露0.2802→0.1807、0.1127→0.3203的明显置信度变化，未把全部差异淡化为舍入误差。IoU诊断只覆盖最差三例，不意味着全量所有高置信度候选已证明严格一致。

代码还有保守计时差异：TRT路径执行显存采样，而原生路径没有同样采样；该开销计入后端wall time，对后端收益不会造成乐观偏置。`decode_d2h_ms` 是 GPU event之外的剩余wall time，含调度/采样开销，不能解释为纯粹PCIe D2H时间。

本复核没有重新计算 COCOeval，也没有重跑 GPU 性能；复核的是实现、保存的逐轮数值、评价范围、当前资源hash和报告与结构化证据的一致性。
